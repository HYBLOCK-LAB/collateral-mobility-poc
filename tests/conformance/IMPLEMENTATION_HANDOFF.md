## 4. 반드시 보존할 연구 범위

- 일정은 약 1주일. **A·B1·B2 모두 구현 대상**이며 A·B1 검증·계측 확보 후 B1을 활용해 B2를 순차 구현한다. 초기 대화의 B2 선택/확장 표현은 최신 합의로 대체되었다. 핵심 비교는 A vs B1, B1 vs B2는 추가 재할당 비용 비교다.
- 국채 100억 원 상당 전체 묶음만 사용한다. 부분 배정·분할·병합은 제외한다.

- 사용 권리·재사용 권한·계약 상태·환매/동등증권 반환 등 의무·CCP 배정과 잠금을 구분한다. owner 변경만으로 대체하지 않는다.
- A는 독립 DB X/Y/Z와 정상 API/이벤트 연계, B1은 공통 S1, B2는 필요한 계약을 X→Y에서 S1→S2로 재할당하고 Y→Z는 S2를 사용한다.
- 실제 현금 결제·CSD·CCP 운영·법률 관계 전체 구현은 범위 밖이다.
- 실행기가 업무 처리·중앙 장부를 대신하지 않는다. 초기 fixture 적재와 실제 거래 처리를 구분한다.

## 7. 검증과 실험에서 빠뜨리면 안 되는 것

- A·B1 최종 인계: 각각 AC-01~11의 필수 변형·반복·증빙 모두 PASS. B2는 AC-01·02·12 모두 PASS. B1만 끝내고 B1·B2 담당 전체 완료로 표시하지 않는다.
- 필수 FAIL·INCONCLUSIVE·NOT_RUN·증거 누락은 최종 인계 불가. 일부 필터 테스트로 전체 완료를 대체하지 않는다. 최종 완료 조건 충족 시만 종료 코드 0.
- 기대된 REJECTED는 정상 테스트 PASS일 수 있다. PENDING/UNKNOWN은 확정 성공·실패가 아니며 기존 요청 결과를 확인한다.
- Schema 검증만으로 통과시키지 않는다. 실제 권한·권리 유효성·의무 보존·단일 효과·배정·이력을 검증한다. 최종 snapshot만으로 일시적 이중 사용 부재를 증명하지 않는다.
- 플랫폼 snapshot은 로컬 범위다. 공통 ID로 필요한 증거를 연결하고 복제 관측을 중복 업무로 세지 않는다.
- 각 독립 테스트·반복은 새 run_id. 명령 request_id는 멱등성 재시도에서 유지하고 호출 attempt_id는 구분한다. 재시도에서 초기화를 다시 하지 않는다.
- JSON Schema의 hyblock.invalid ID는 식별자다. 온라인 다운로드가 아니라 저장소 로컬 Schema 참조로 검증한다.
- 모의 서버/준비 명령은 실행기 자체 시험용으로만 사용한다. 실제 A·B 통과·금융 업무 구현·연구 측정으로 보고하지 않는다.

계측 원문은 measurement.md를 읽고 적용한다. 특히:

- 단조 시계 나노초 정수 문자열. 서로 다른 프로세스 시계를 빼지 않는다. 내부 확정 시각과 관측기 최초 확정 수신을 구분한다.
- T_End-to-End = T_Availability + T_Waiting + T_Completion. 실행별로 계산한 뒤 집계하며 구간별 P95 합산 금지.
- T1 워밍업 3회 + 본 시도 30회. 실패를 빼고 성공 30회까지 보충하지 않는다.
- AC-08/09/10 각 10회, T3 5회, B2 정상 30회에서 재할당 함께 수집.
- readiness 응답 후 10ms, 결과 조회 응답 후 50ms. HTTP 대기 5초, T3 추가 지연 10초, 복구 재제출 최소 1초 간격·추가 최대 3회, 본문 관측 한도 60초.
- HTTP 라이브러리의 read timeout만으로 전체 호출 5초 한도가 보장되는지 별도로 확인한다. 관측 한도와 네트워크 단계별 대기를 혼동하지 않는다.
- P50/P95 nearest-rank, 표본 0개는 null. 정상 성공의 시간 통계와 전체 시도·거부·미완료·무효 건수를 함께 보고한다.
- 정상·경합·장애·재할당 결과를 구분한다. 느리다는 이유로 제외하지 않는다. 순서·환경·내구성·버전·자원 설정을 보존한다.

## 8. 합의된 지연 주입과 B2 증빙

### T3 / AC-11

- 총괄의 작은 로컬 중계 기능이 최초 Y 제출을 전달하고 첫 응답을 받은 뒤 10초 보류한다. 요청자에는 실제 5초 타임아웃이 발생하게 한다.
- 클라이언트가 이미 응답을 받은 뒤 sleep하는 방식은 안 된다. 업무 처리·내부 확정은 중단하지 않으며 클라이언트 연결 종료로 원래 명령을 취소하지 않는다.
- 복구 조회·후속 재전송은 계속 차단하지 않는다. 새 장애 범위를 추가하지 않는다.
- FAULT_ACTIVATED, RESPONSE_HELD, FAULT_RELEASED 등 기존 이벤트와 내부 확정 증거를 연결한다. 실제 보류 시작·해제·구간을 남긴다.
- 첫 응답이 PENDING이거나 확정 증거가 부족하면 확정 결과 응답 지연 재현으로 인정하지 않는다. 정상 처리 자체 지연과 주입 지연을 구분한다.
- 타임아웃 후 연결이 닫혀 응답 전달이 실패해도 보류·해제 기록과 원래 거래의 단일 효과는 확인한다. 프로세스 중단·DB 손실 복구를 검증했다고 확대하지 않는다.

### B2 / AC-12

- 후속 사용에 필요한 계약 전체 목록·선정 이유, 공통 업무 참조↔Contract ID, 재할당 ID, 실제 source/target과 S1/S2 별칭 연결, 실제 Unassigned/Assigned 이벤트 원본을 수집한다.
- 기존 event Schema와 evidence/를 재사용한다. 사용할 Canton 버전의 API·권한·수집 경로는 실제 환경에서 확인해야 한다. 과거 공식 문서 검색 결과만으로 특정 버전 지원을 단정하지 않는다.
- 계약별 시작·완료·S1 사용 불가·S2 사용 가능 시점을 같은 시계 원칙으로 기록한다. 누락·역전·관측 한계는 표시하고 추정값을 채우지 않는다.
- 필요한 계약 전부의 사용 조건 확인 후 Y readiness 인정. Y readiness 하나를 계약별 증빙 대신 쓰지 않는다.
- 실제 성공 계약 수 N_RA, 논리 경계 전환 1회, 배치/API/재시도 수는 구분한다. 전체 준비 구간을 계약별 시간 합으로 대체하지 않는다. 재할당 시간을 E2E에 중복 가산하지 않는다.

## 9. 결과물과 발표 활용

- 로컬 results/<배치ID>/에 보관한다. 배치는 여러 run_id를 묶는다. 기존 배치를 덮어쓰지 않는다.
- manifest.json: 설정·환경·버전·실행 순서·fixture 해시 등 재현 기준.
- events.jsonl, evidence/: 원본 관측·응답·snapshot·구현 로그. 비밀값 제외.
- checks.json: 테스트·변형·판정·증거 참조.
- runs.csv: 실행별 값·상태·유효성·제외 사유. summary.csv: 공통 규칙 집계.
- report.md와 figures/(PNG·SVG): 고정된 수치표·그림. report 재실행은 시스템을 재실행하거나 원본을 바꾸지 않는다.
- 발표용 확정 결과는 선별해 GitHub에, 대용량 원본은 별도 공유 보관소에 보존한다. 보관소는 미정이다. 자동 업로드·커밋은 만들지 않는다. 결과 파일이 생기기 전 무심코 원본·인증·로그가 커밋되지 않도록 ignore 범위를 확인한다.
- 지연시간 3지표는 실행별 분포·P50/P95, 정합성은 위반·증거 표, 복구는 시간·조회·재시도·미완료, B2는 재할당 비용과 B1 비교를 제공한다.
- 플랫폼 연결 복잡성은 자동 로그만으로 완성할 수 없다. 구조·인터페이스·모듈 변경·메시지·예외 경로의 근거를 총괄이 검토한다. 임의 총점 만들지 않는다.

## 10. 새 세션의 실행 순서와 검증

1. 실제 repo의 AGENTS·status·기존 구현·위 문서들을 읽는다. 현재 추가된 작업을 보존한다.
2. 승인된 최소 스택을 실제 환경에서 준비하고 버전을 기록한다. 접근 제한은 정식 권한 요청으로 처리한다.
3. 설정·fixture 입력과 로컬 Schema 참조, 실행 ID·배치·기록 저장을 구현한다.
4. 준비 명령 호출·결과 검증·초기 snapshot 검증을 구현한다. 실제 적재 코드는 구현 구조를 확인할 수 있는 모델부터 연결한다.
5. 실행기 자체 시험: 잘못된 설정/fixture, 준비 실패/불일치, 잘못된 초기 권리·의무 상태, 기존 실행 충돌, 인증정보 기록 누출 방지를 작은 재현으로 확인한다.
6. 첫 범위의 실제 실행과 모의 실행·미연결 상태를 분리 보고한다. 실제 시스템이 없다는 이유로 실행기 기반 기능 작업 전체를 중단하거나 실제 구현을 대신 만들지 않는다.
7. X→Y 정상·거절·멱등성·경합·복구 → Z·완료 판정 → 반복·집계 → 고정 그래프 → B2 연결 순으로 완성한다. 후속 기능도 필수 범위이며 선택 사항이 아니다.
8. 판정 누락이 통과되지 않는지, 시간 계산·P95·표본 제외·재집계 결과가 기대값과 맞는지 시험한다. 실제 시스템 연결 후 공통 테스트를 다시 수행한다.
9. 단계별 변경·실행 검증·미실행·연결 의존성을 보고한다. 사용자 확인 없이 커밋·푸시하지 않는다.

미확정 연결 지점은 모델별 실제 주소·인증 전달 방식·DB/계약 구조·권한·로그 위치·Canton 버전/이벤트 경로다. 통과 기준을 약화하거나 예시값을 실제값으로 취급해 해소하지 않는다. 기술 스택·기록 방식 등 이미 승인된 결정을 반복 질문하지 않는다.

## 12. 후속 구현 이후 인수 지점

- `prepare`, 선택/전체 `check`, `check --final`, 고정 시도 `experiment`, 원본 기반 `report`가 구현돼 있다. 실제 A/B가 없으면 준비·증거·선행 검증 누락을 기록하며 통과/0ms로 채우지 않는다.
- 소스: runner.py, checks.py, fault_proxy.py, report.py. 실제 실행기의 로컬 연결 규약은 README 제14절에 있고 공통 HTTP·Schema·fixture는 바꾸지 않았다.
- 자체 시험은 준비·모든 X/Y/Z 변형·응답 중계·내부 이력·증거 누락/훼손·고정 일정·통계·재생성·B2 계약/호출 증거를 대상으로 한다. 모의 시험을 실제 A/B 연구 결과로 사용하지 않는다.
- X/Y 실행기 시험 후 Z 실행기를 추가하기 전의 소스·시험 근거는 `results/development-baselines/xy-runner/`에 보존했다. 실제 모델의 X/Y 기준 커밋이 아니며 커밋·푸시는 실행하지 않았다.
- 남은 실제 연결: A/B DB·Daml 구조와 적재 프로그램, 실제 주소·인증 전달, 원본 로그의 정규화·flush·attempt 매핑, 모델 버전/환경/기준 커밋/Z 변경 근거, Canton 버전·Party·Synchronizer·실제 원본 이벤트 수집.
- B2는 실제 A/B1 검증·계측 근거가 먼저 필요하다. 실행기 코드가 있다는 이유로 이를 건너뛰거나 실제 모델의 Z/B2가 완성됐다고 보고하지 않는다.
- 다음 작업은 실제 구현 담당자가 제공한 구조·기동·권한·로그 정보를 확인하여 총괄 담당의 적재/수집 연결을 작성하고 실제 시스템에서 공통 테스트를 재실행하는 것이다. 데이터 계약이나 핵심 판정 변경, 커밋·푸시는 사용자 확인을 받는다.
